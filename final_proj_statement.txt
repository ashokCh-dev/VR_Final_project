Visual Product Search Engine
Visual Recognition Course Project
Problem Statement & Motivation
Students often face a simple problem in online shopping: they see a product image they like, but
cannot find similar items using text search.
Most e-commerce search systems rely on product titles and tags. This causes two common issues:
• Language mismatch: users type simple words like ”black hoodie”, while catalog descriptions
may use different or technical terms.
• Inconsistent metadata: different sellers describe the same type of product differently, so
keyword search becomes unreliable.
To solve this, this project builds a query-by-image product search system. Instead of searching
by text only, the user uploads an image, and the system returns visually and semantically similar
products.
We use the DeepFashion In-Shop Clothes Retrieval dataset. Images with the same item id
are treated as the same product for training and evaluation.
The system has two parts:
• Offline indexing: prepare product embeddings and store them in a vector index.
• Online retrieval: process a query image and return top matching products quickly.
System Architecture
Offline Indexing Pipeline
For each catalog image, the system performs the following steps:
Step 1. Product localization (YOLO). The detector identifies the primary clothing item and crops
the image to reduce background noise.
Step 2. Semantic captioning (BLIP-2). A BLIP-2 captioner generates a consistent product description (e.g., color, fit, material, and style details).
Step 3. Cross-modal embedding (CLIP). The cropped image embedding and caption embedding
are fused into a single normalized vector:

Step 4. Approximate Nearest Neighbor (ANN) indexing using Hierarchical Navigable Small
World (HNSW). The fused vectors, item IDs, and metadata are stored in a vector index (e.g.,
Pinecone or Milvus) for fast nearest-neighbor search.
Online Query Pipeline
Given a user query image q, retrieval proceeds as follows:
Step 1. Query preprocessing. YOLO crops the main product region from the query image.
Step 2. Query encoding. The cropped query is mapped to a CLIP visual embedding.
Step 3. Candidate retrieval. The system searches the ANN index and returns top-K candidates using
cosine similarity.
Step 4. Semantic re-ranking (BLIP-2 ITM). A BLIP-2 image-text matching score is computed for
each candidate caption with the query image, and candidates are re-ranked to produce the final
result list.
In summary, YOLO improves visual focus, BLIP-2 improves semantic consistency, CLIP aligns
image and text signals, and HNSW enables low-latency retrieval at scale.
Fine-Tuning Strategy
We use pre-trained CLIP, BLIP-2, and YOLO models. For this project, we only fine-tune CLIP.
BLIP-2 and YOLO stay frozen.
CLIP Fine-tuning
Goal. Put images of the same item id closer in embedding space, and push different items farther
apart.
What we update.
• Fine-tune CLIP vision encoder (last 4 blocks at minimum; full encoder if compute allows).
• Keep CLIP text encoder frozen.

Metrics
We use three standard retrieval metrics.
Metric Meaning
Recall@K Fraction of queries for which at least one relevant
item is retrieved in the top-K results.
NDCG@K Ranking metric that gives higher score when
relevant items appear earlier in the top-K list
(position-aware gain).
mAP@K Mean of per-query average precision up to K,
rewarding systems that retrieve relevant items and
place them in better rank positions.
We report results at K ∈ {5, 10, 15}. For example, Recall@5 checks only the top 5 returned products.
